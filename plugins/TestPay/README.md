# TestPay (테스트 결제)

개발·테스트 환경에서 실제 PG 없이 결제 흐름을 끝까지 돌려 보는 가상 결제 플러그인입니다. 결제창 대신 확인 모달을 띄우고, 확인을 누르면 결제가 즉시 성공합니다.

**돈이 오가지 않고 어떤 주문이든 결제 완료로 만들 수 있으므로 운영 환경에서는 절대 동작하지 않아야 합니다.** 그래서 이 플러그인은 활성화돼 있어도 `APP_ENV` 가 개발 환경 값일 때만 결제 수단으로 등록됩니다.

- **요구 사항**: Mublo Core 1.0.0 이상
- **설정 화면**: 없음 (활성화만 하면 됩니다)

## 언제 등록되는가

| `APP_ENV` | 결제 수단 등록 |
|-----------|----------------|
| `local`, `development`, `dev`, `testing` | 등록됨 |
| 그 밖의 모든 값 (`production`, `prod`, `staging`, 대소문자 변형, 빈 값 등) | **등록 안 됨** |
| 설정 안 함 | 등록 안 됨 (기본값을 `production` 으로 봅니다) |

허용 목록(화이트리스트) 방식입니다. 모르는 값은 거부하므로 `APP_ENV=prod` 같은 오타가 '공짜 결제 허용'으로 이어지지 않습니다. 목록은 코어 `DomainVerificationService` 가 개발용 우회를 허용하는 환경 목록과 같습니다.

등록되지 않으면 결제 수단 목록에 나타나지 않고, 요청에 `testpay` 를 직접 실어 보내도 해당 게이트웨이가 없어 결제가 진행되지 않습니다.

## 결제 흐름

```
prepare()   거래번호 TEST_{금액}_{일시}_{난수} 발급 + 확인 모달 스크립트
  └ 확인 모달
      ├ 확인  → verify(거래번호) → 소비 패키지가 금액 대조 후 결제 완료
      └ 취소  → 'mublo:pay' cancel 신호
cancel()    항상 성공 (실제 환불 없음)
```

- `verify()` 는 `TEST_` 로 시작하는 거래번호만 성공으로 보고, 거래번호에 담긴 금액을 돌려줍니다. 소비 패키지(Shop 등)는 이 금액을 주문 금액과 대조합니다.
- 결제창 표시 방식은 `mublo:pay` 이벤트 계약을 따릅니다. 화면 복원은 소비 패키지가 맡습니다.

## 알려진 제약

- 실제 PG 의 실패·지연·중복 통보 같은 상황은 재현하지 않습니다. 그런 흐름은 각 PG 플러그인의 테스트 모드로 확인하세요.
- 가상계좌 등 결제수단별 흐름은 흉내 내지 않습니다.
